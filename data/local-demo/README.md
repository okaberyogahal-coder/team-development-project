# 共有する開発用ユーザーと履歴

本番DB完成までの一時的なJSON保存先です。すべて架空のサンプルです。本物のメール・パスワード・個人情報を記入しないでください。

- `materials.json`：教材。公開状態・分野・説明。
- `users/photography.json`：そら（架空）。写真と花の初期履歴。
- `users/food-photo.json`：あおい（架空）。写真と料理の初期履歴。
- `users/newcomer.json`：はる（架空）。初期は履歴なし。

`npm run dev:ai-navi` で起動し、`http://localhost:3002/login` の「開発用ユーザーでログイン」からユーザーを選びます。ログイン後は `/avatar` でプロフィール・衣装を設定してからワールドへ進めます。AIナビの履歴保存を試す場合は `/ai-navi` の「サンプル教材を開いて履歴を記録」で閲覧を保存し、詳細の「受講完了を記録」で完了を保存します。閲覧だけでは完了になりません。

UIからの操作でこれらのJSONが更新されます。VS Codeで変更を確認できます。再読込・サーバー再起動後もファイルの履歴は残ります。セッションはブラウザのHttpOnly Cookieと起動中サーバーのメモリだけに保持します。8時間またはサーバー再起動・ログアウトで失効し、Gitには入りません。テスト専用のパスワード照合で、本番会員認証ではありません。

## Gitで共有する

1. サーバーをCtrl+Cで停止する。
2. `git diff -- data/local-demo` で変更したJSONを確認する。
3. 必要なJSONだけをコミット・プッシュする。
4. 他のメンバーもサーバー停止後にプルする。
5. `npm run dev:ai-navi` で再起動し、自分のブラウザでテストアカウントにログインする。

Gitはリアルタイム同期しません。ユーザーごとにファイルを分けていますが、同じファイルを別々に編集すれば競合する場合があります。競合時はサーバーを止め、JSONの構造と履歴を確認して解消します。自動リセットはありません。サーバー起動中の手編集・プル・複数サーバーによる同時更新は対象外です。

## データの形式

各ユーザーは `schemaVersion`, `id`, `nickname`, `description`, `events`。ユーザーIDとファイル名は固定です。

履歴は `id`, `materialId`, `kind`, `at`。kindは `view` または `complete`、idは `view:教材ID` または `complete:教材ID`、atはUTCのISO日時（例 `2026-10-24T00:00:00.000Z`）です。同じユーザー・教材・kindの再操作は日時更新となり、重複履歴を増やしません。

初期日時は自動で現在時刻へ書き換えません。30日を過ぎた記録は人気集計から外れます。人気は保存した全架空ユーザーの実際の記録だけから計算し、80%以上を対象とします。初期データでは写真教材が2人中2人、花飾りと料理はそれぞれ2人中1人です。以前の固定5人の架空集計はこの経路には使いません。

破損・欠落時はエラーにし、空データで上書きしません。修復はサーバー停止後に行ってください。既存履歴を破棄する `git restore` 等の操作は、必要な変更がないことを確認してから行います。

## DB完成後

保存処理は `server/local-demo/repository.ts` の `LocalDemoRepository` に集約しています。DB用の実装へ置き換える際は、実会員ID・本人認証・同意・保存期限・履歴移行を別途調整します。このJSONや開発用Cookieを本番の本人確認には使いません。

これは共有する架空アカウントです。公開されたテスト専用パスワードのため、実サービスや個人アカウントで使用しないでください。

`credentials.json` は3人のユーザーID・架空メール・個別salt・scryptハッシュを持つサーバー専用ファイルです。平文パスワードはJSONに保存せず、ブラウザ向けAPIにも返しません。ID指定ログインとユーザー切替ボタンは廃止しました。別ユーザーへ移るときはログアウトして再ログインします。新規登録画面は従来の画面体験のみで、ここにアカウントを追加しません。

ログイン失敗は全ユーザー合計で10分20回までです。上限時は時間を置くか開発サーバーを再起動します。Gitで共有するのは資格情報のテスト用ハッシュと履歴であり、セッショントークンは共有しません。メール確認・パスワード再設定・本番DB移行は別対応です。
