# ミライフ 独自2D交流空間 詳細設計

更新日：2026-10-06
状態：文書レビュー承認済み。PC版の空間・共有通信・通話連携を実装。実映像・音声はLiveKit Cloud設定後に検証する。

## 1. 目的と範囲

世代を超えた交流のため、独自の2D空間をアバターで移動し、複数の部屋で音声・ビデオ通話できる体験を提供する。独自の画面・マップ・アバターを制作し、通話は既存基盤を組み合わせる。

ユーザーとの合意事項は、独自空間、数十人でのテスト、同じ部屋に入った人同士の通話、テスト段階はPC、仮完成時はスマートフォン・タブレット対応である。

初期設定は全体50人、4室、各室8人。ロビーと切断時の予約枠も全体人数に含む。4室の合計32人に加え、残りはロビーで待機・移動できる。50人対応は検証目標であり、実測前に達成済みとしない。

旧設計の「最大10人・通話なし・施設は活動パネルのみ」を置き換える。近接通話、3D・VR、録画、画面共有、文字チャット、アカウント、実AI、予約はPCテスト版の対象外。

## 2. 画面と操作

既存トップページから `/plaza` に移動する。ニックネームは前後空白を除く1〜20文字。用意されたアバターを選び、ゲスト参加する。同名を許容し内部IDで識別する。

入場前に任意のカメラ・マイク確認を用意する。機器アクセスは利用者の操作時に要求する。確認用ストリームは確認終了・入場・画面離脱時に停止する。実通話はカメラ・マイクともオフで開始し、各参加者がオンにする。機器なし・権限拒否でも空間に参加できる。

ロビーと各室をSVG・HTMLで描画する。明るい配色、大きな日本語ラベル、人物と名前を用い、色だけで状態を区別しない。PCは矢印キー・WASDで移動し、クリック・キーボードで操作できる部屋一覧から入室する。マップの入口でも同じ入室操作を提供する。入力欄へのフォーカス・画面非アクティブ・通信断では移動を止める。

初期の部屋は交流カフェ、趣味の部屋、学びの部屋、経験共有の部屋。人数と空き状況を表示する。ロビーは通話なし。各室では参加者名・映像・機器状態・通話状態、ロビーへ戻る操作を表示する。部屋移動後は機器をオフで開始する。

仮完成時にタッチ方向操作を追加し、タッチ終了・キャンセルで停止する。小画面では通話パネルを折りたためるようにする。PC段階からマップ座標と表示サイズ、入力処理と移動規則を分離する。

## 3. 構成と責務

Next.js App Router・TypeScript・Tailwind CSSを継続利用する。常駐Node.js共有サーバー1台がID、所属、位置、人数、接続世代を管理する。ブラウザーとはWebSocketで通信する。PCテスト版では複数サーバーへの分散やDBを導入しない。再起動で参加状態は消える。

通話は複数人の映像を中継する既存のSFU型基盤を利用する方針。実装計画でLiveKit CloudとJavaScript SDKを選定した。公開構成と費用は公開工程で確認する。特に部屋からの強制切断と再入室権限の制御を提供する基盤を選ぶ。コード連携は実装済みで、実通話にはCloudの接続設定が必要。

共有サーバーの所属を通話権限の根拠とする。ブラウザーが指定した部屋IDだけでトークンを発行しない。現在の所属を確認し、部屋・参加者を限定した短時間のトークンを渡す。秘密鍵はサーバーのみで保持する。

位置共有と通話は別の接続状態として管理する。通話失敗時も在室状態と通話成功を混同せず、再接続・ロビーへ戻る操作を提供する。

## 4. 入室・部屋変更の整合性

全体入場と部屋入場はサーバーで同期的に定員判定・枠確保する。入室処理中と切断後の予約も人数に含む。画面の空室表示だけを根拠に入室しない。

部屋変更は以下の順序で行う。

1. 移動先の定員を確認し予約枠を確保する。満員なら元の部屋を維持する。
2. クライアントは音声・映像公開を止め、旧通話を切断する。サーバーも通話基盤で旧接続を停止し、旧部屋への再入室を禁止する。
3. 旧接続の停止を確認してから所属変更を確定し、元の枠を解放する。
4. 新しい部屋限定のトークンを発行し、機器オフで新通話へ接続する。

旧接続の停止を確認できない場合は新トークンを発行せず、移動先予約を解放して復旧案内を表示する。予約は10秒で失効する。所属確定後に新通話へ接続できなければロビーへ戻す。要求IDと接続世代で遅延・重複結果を識別し、移動中は追加移動要求を拒否する。

ロビーへ戻る・全体退出・異常切断でも通話を停止する。トークンの期限切れだけに頼らず、基盤側の接続切断と再入室拒否を必要とする。実装ではCloudのRemoveParticipantに明示的な失効時刻を渡す。実Cloudでの失効挙動は接続設定後に確認する。

## 5. データと通信契約

参加者情報はID、表示名、アバター、所属部屋、座標、向き、接続状態、接続世代。秘密鍵・通話トークン・再接続トークンは他参加者に配信しない。マップの座標範囲・出現位置・衝突領域・入口をクライアントとサーバーで共有する。

| 方向 | メッセージ | 内容 |
| --- | --- | --- |
| クライアント→サーバー | join | 名前・アバター・再接続情報 |
| クライアント→サーバー | move | 移動方向・連番 |
| クライアント→サーバー | changeRoom | 移動先・要求ID |
| クライアント→サーバー | leave | 全体退出 |
| サーバー→クライアント | welcome | 自分のID・再接続情報・所属・部屋一覧 |
| サーバー→クライアント | state | 同室の位置情報・全室人数 |
| サーバー→クライアント | roomChanged | 確定した所属・出現位置 |
| サーバー→クライアント | callCredentials | 現在の部屋限定の接続情報 |
| サーバー→クライアント | error | 満員・不正入力・通話失敗・期限切れ |

サーバーが20Hzで移動を計算し、10Hzで同室へ状態を配信する。入力は方向のみとし、斜め速度を正規化、範囲・衝突を判定する。500ms入力がなければ停止。メッセージは4KB以下、毎秒30件以下とし、不正な数値・未知の部屋・アバターを拒否する。表示名をHTMLとして解釈しない。

## 6. 切断・復帰・運用

明示的退出は直ちに全体・部屋の枠を解放する。異常切断では移動と通話を停止し、30秒だけ枠を保持する。10秒ごとに疎通確認し、20秒応答がなければ切断扱い。復帰は1・2・4・8秒間隔、その後8秒間隔で試みる。猶予終了後は再度定員を確認する。

推測困難な再接続トークンをタブのsessionStorageに保存する。同じ参加者の二重接続は新接続へ置き換え、旧接続終了で新状態を消さない。復帰時は通話トークンを再発行し機器をオフへ戻す。サーバー再起動後は入場をやり直す。

公開環境はHTTPS・WSS、Origin許可リスト、入力制限を使用する。ログは接続数・エラー・状態遷移のみを対象とし、秘密情報・映像・音声を保存しない。テストは関係者に共有する環境で行う。有料契約・一般公開・ドメイン変更は設計承認に含めない。

## 7. 実装単位

- `app/plaza/page.tsx` と `app/components/plaza/`：入場、マップ、参加者、部屋選択、通話UI。
- `app/hooks/`：位置共有と通話を分離した接続状態管理。
- `shared/plaza/`：部屋定義、通信型、入力検証、移動規則。
- `server/`：人数、所属、位置、再接続、通話権限と基盤連携。
- 既存ヘッダー・ヒーロー：交流空間への入口。

機器停止と通話退出は接続管理の責務とし、画面の描画処理に依存させない。

## 8. 受入条件

1. 異なるPCの参加者間で、同室の名前・位置・移動を共有できる。
2. 30接続・50接続で入場・移動・部屋変更を試験し、51人目を拒否する。
3. 各室8人まで参加し、競合する9人目を拒否する。退室で枠が空く。
4. 複数部屋で並行通話し、同室だけで音声・映像を共有する。部屋外のトークン取得・退出後の再接続を拒否する。
5. 入退室、切断、連続した部屋変更でも旧部屋への送信・旧部屋からの受信が残らない。
6. 権限拒否、機器なし、通話失敗でも退出・再試行できる。
7. 自動接続の試験と実端末の通話試験を分けて記録する。各室8人・4室並行の通話は実端末で確認してから対応を主張する。
8. 安定したネットワークで移動反映300ms程度以内を目標に測定する。通話の途切れ・接続時間・CPU・帯域・人数・試験時間を記録する。
9. 型検査・ビルドと、人数・所属・移動・接続世代・権限の自動テストを実施する。品質は実端末でも確認する。
10. 仮完成時はスマートフォン・タブレットの実機でタッチ移動・入退室・通話・回転・背景復帰を検証する。
