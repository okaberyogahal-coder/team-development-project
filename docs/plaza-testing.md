# 交流空間の起動・検証

更新日：2026-10-06

## ローカルで試す

依存導入は `npm install`。ターミナルを2つ使う。

```sh
npm run dev -- --port 3002
npm run dev:plaza
```

http://localhost:3002/plaza を開き、名前とアバターを選ぶ。矢印キー・WASDで移動し、建物の「入る」か部屋一覧から移動する。2つのタブまたはブラウザーで参加すると他のアバターが見える。部屋一覧はクリックとキーボードで操作できる。

localhostは手元のPC専用。同じWi-Fi・LANの別PCから参加する場合は、次の手順を使う。

## 同じWi-Fi・LANの別PCから参加

既存の開発サーバーを停止し、ホストのMacで次を実行する。

```sh
npm run dev:lan
```

画面と共有サーバーをまとめて起動し、参加用URLを表示する。現在のURLは `http://10.77.98.69:3002/plaza`。他のPCを同じWi-Fi・LANにつなぎ、そのURLをブラウザーで開いて名前とアバターを選ぶ。他のPCへのインストールは不要。ホストのMacとこのコマンドを起動したまま使う。

ネットワークが変わるとIPも変わるため、再起動時に表示されたURLを使う。接続できない場合は同じネットワークか、Wi-Fiの端末間通信制限とMacのファイアウォールでTCP 3002・3003が遮断されていないか確認する。

この手順はアバター・移動・部屋の共有用。LANのHTTP画面ではカメラ・マイクの利用にHTTPSが必要。別のネットワークからの参加にも、HTTPSの画面とWSSの共有サーバーを公開する構成が必要。

## 通話設定

`.env.example` の設定をローカルの `.env.local` に記入する。LiveKit CloudのプロジェクトからURL・API key・API secretを取得する。秘密値はチャット、ドキュメント、Gitへ貼り付けない。設定変更後に両サーバーを再起動する。

| 設定 | 用途 |
| --- | --- |
| NEXT_PUBLIC_PLAZA_WS_URL | 空なら画面と同じホストの3003へ自動接続。公開時はWSSの接続先を指定 |
| PLAZA_PORT | 共有サーバーのポート。既定3003 |
| PLAZA_ALLOWED_ORIGINS | 空ならlocalhostとホスト自身のLAN IPv4を許可。公開時はHTTPSの画面Originを指定 |
| LIVEKIT_URL | wss://…livekit.cloud形式のCloud接続先 |
| LIVEKIT_API_KEY / LIVEKIT_API_SECRET | サーバー専用の通話資格発行・失効設定 |
| LIVEKIT_ROOM_PREFIX | このアプリ専用の部屋名prefix。別用途のプロジェクトと共有しない |

設定がすべて空の場合は通話未設定として起動し、ロビー・移動・部屋変更を使える。部分的に設定された場合やCloud接続準備に失敗した場合は共有サーバーの起動を止める。self-hosted LiveKitは今回の即時失効条件を満たさないため許可しない。

部屋入室では通話に接続するが機器はオフ。利用者がカメラ・マイクをオンにする。入場前の機器確認は映像・音声を他の参加者に送らず、確認終了で停止する。録音・録画は実装していない。

起動時は専用prefixの4室について残存参加者を切断・失効させる。常駐共有サーバーは1インスタンスで運用する。同じprefixを複数サーバーで共有しない。

## 自動検証

```sh
npm test
npx tsc --noEmit --incremental false
npm run build
npm run load:plaza -- --clients 30
npm run load:plaza -- --clients 50
npm run test:browser
```

負荷試験は独立した空きポートの共有サーバーを起動するため、利用中の広場の人数を変えない。通話は行わない。

ブラウザー試験は画面3002の起動が必要。専用の共有サーバー3005を自動起動し、テストブラウザーだけをそちらへ接続するため、利用中の広場の人数と混ざらない。現在の `playwright.config.ts` はこのMacのChrome実行ファイルを利用する。他環境ではその設定を変更する。スクリーンショットは `/tmp/melife-plaza-entry.png`、`/tmp/melife-plaza-lobby.png`、`/tmp/melife-plaza-room.png`。

Next.jsビルドと開発サーバーを同じ `.next` に同時出力しない。ビルド前にNext開発サーバーを止め、終了後に再起動する。

## 2026-10-06の確認結果

- Node単体・WebSocket統合テスト：36件成功。
- Chromeの2ブラウザー：入場・アバター移動・部屋変更・部屋ごとの表示分離・退出、初期描画エラーなし、キー長押しでも切断しないことを確認。
- Chrome試験は3件成功。LANのIPアドレスとlocalhostの2ブラウザーで参加・人数同期・部屋変更を確認。物理的な別PCでの参加は未検証。
- 30接続の位置共有試験：PASS、最終実行のローカル位置反映68ms。
- 50接続の位置共有試験：PASS、最終実行のローカル位置反映63ms。
- 型検査・Next.js本番ビルド：成功。最後のビルドは利用中の開発サーバーを維持するため、同一ソースの一時コピーで実行。
- 全体51人目、部屋9人目の拒否を確認。
- 通話資格の部屋・identity・カメラ/マイク限定を署名検証で確認。
- 実際の音声・映像、Cloud上のtoken失効、各室8人・4室並行通話、遠隔ネットワーク、スマートフォン・タブレットは未検証。

位置反映時間は手元のPC上の自動接続1回の値であり、遠隔ネットワーク性能や50人のビデオ通話能力を示さない。Cloud設定と実参加者を用意して実通話を検証した後に、通話対応人数を確定する。

## 実通話の受入手順

1. 2台のPCで同室参加し、互いの映像・音声を確認する。音声のみ・機器拒否・機器切断・音声再生開始操作も確認する。
2. 別室へ移動し、旧部屋への送信・旧部屋からの受信がなくなることを確認する。
3. 入場直後、token更新直後、退出済み参加者で、旧資格を再利用してもCloudへの再入室が拒否されることを確認する。秒単位の失効cutoff境界も確認する。
4. Cloud API障害、ネットワーク断、移動連打、接続中の退出と復帰で、旧通話が残らず状態表示が正しいことを確認する。
5. 各室8人、4室並行で通話を行い、人数・端末・ブラウザー・接続時間・CPU・帯域・音の途切れ・継続時間を記録する。
6. 公開環境のHTTPS/WSSとOrigin設定で遠隔参加を検証する。公開・契約操作は別途承認後に行う。
