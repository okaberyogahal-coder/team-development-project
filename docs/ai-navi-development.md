# AI未来ナビの開発状態

2026-10-26：登録済みテストアカウントのメール・パスワードログインに対応。本番の本人認証・実履歴の保存は未接続。実APIの意味的な提案品質はキー設定後に確認する。

## 目的と表示

本人に好きなことや希望を説明させるのではなく、体験・閲覧・受講履歴の関連性から新しい楽しみを提案する。教材選定を主目的にはしない。

体験版には、希望を申告していない「写真の受講完了＋花飾りの閲覧」「写真の受講完了＋料理の閲覧」「履歴なし」の3ケースを用意した。各ケースに対応するテストアカウントで確認する。本番の希望入力ではない。

提案は最大3件。「趣味・テーマ名」「なぜ合いそうか」「最初に試せること」「根拠となる履歴または人気」を表示する。関連教材は任意の補助案内。教材なしでもテーマを提案できる。

## 実装と境界

- `server/ai-navi/demo-data.ts`：固定サンプルの履歴と教材。履歴IDに閲覧・完了の種別を含め、個人名・他人の個別履歴はAIへ渡さない。
- `server/ai-navi/popularity.ts`：直近30日（開始境界を除く）のユニーク教材利用者を分母とし、利用率80%以上を人気とする。閲覧・完了・再読込の同一人は重複計上しない。実データなしは割合null。
- `server/ai-navi/candidates.ts`：教材の一次抽出。体験版は履歴だけを使い、申告した興味や目標は渡さない。
- `server/ai-navi/openai.ts`：Responses APIに構造化した履歴と教材を送り、テーマを生成する。store:false、自動再試行なし、20秒打切り。
- `server/ai-navi/output.ts`：テーマ・理由・最初の行動を検証。履歴根拠は渡した履歴ID、人気根拠は集計で人気の教材IDに限定する。閲覧を完了へ変えたID、未知の教材、重複テーマ、不正形式を拒否する。
- `server/ai-navi/demo-handler.ts`：本文は空オブジェクトのみを受け付け、認証済みセッションからJSONの本人履歴を読み、入力サイズ・Origin・ローカルHost・開発用有効化を確認する。60秒3回、同時1回。上流のエラー本文やAPIキーを画面に返さない。

履歴なしでは人気を入口と明示し、本人の体験を発見したと装わない。自由文の意味的な正しさや「好き」「習得」等の断定を構造検証だけで保証はできない。プロンプトで抑制し、実モデルで品質評価する。

## 起動手順

1. `.env.local` に `OPENAI_API_KEY` と `OPENAI_MODEL` を設定する。キーをチャットやGitに貼らない。モデルは利用アカウントで利用可能なResponses API・Structured Outputs対応IDを指定する。
2. `npm run dev:ai-navi` で起動し、`http://localhost:3002/login` を開く。
3. `data/local-demo/README.md` のテストアカウントでログインして履歴を確認し「履歴からテーマを見つける」を押す。サンプルがOpenAIへ送信され、APIの従量料金が発生する。

専用コマンドは127.0.0.1:3002へ固定し、任意の起動引数を拒否する。通常のdev・dev:lan・本番では体験版は404。有効化フラグMILIFE_AI_NAVI_DEMOを他の起動環境や.envへ設定しない。

設定を変更したらサーバーを停止・再起動する。ビルド前にも開発サーバーを停止する。同じ.nextへ同時に開発・本番生成物を書き込むとキャッシュが不整合になる。

Next.js14のURL正規化による既知の制約があるため、127.0.0.1表記ではなくlocalhostで開く。開始済みOpenAI処理の課金取消は保証しない。回数制限は開発プロセス単位であり、再起動でリセットされる。

## DB接続までの共有JSON保存（2026-10-26更新）

現在の開発体験版は固定ケース選択から、共有JSONのテストアカウント認証へ移行した。`data/local-demo/materials.json` と `data/local-demo/users/*.json` をGitで共有できる。手順と形式は `data/local-demo/README.md` を参照。

専用起動後、`/login` の既存メール・パスワード欄から登録済みの架空ユーザーでログインする。`/ai-navi` でログアウトでき、教材を開くと閲覧、明示操作で受講完了を保存する。保存したJSONを元にAI入力と人気を作る。別タブの選択変更、履歴更新、ログアウト前の古い応答は表示しない。

人気の固定5人データは、このJSON接続経路では使用しない。全共有ユーザーの保存済み記録から直近30日の割合を計算する。初期JSONの日時は2026-10-24T00:00:00.000Zで、自動的に再日付しない。古くなれば集計対象外になる。

資格情報はサーバー専用 `credentials.json` に個別salt付きscryptハッシュとして保存する。セッションCookieはHttpOnly・SameSite=Laxで8時間。セッションはプロセス共有メモリのみで、再起動でも失効し、Gitに入れない。保存対象は架空データのみで、本番のログイン認証や権限保護ではない。登録体験とUnityの外見保存は既存のブラウザ保存のまま別機能として維持する。

ファイル更新はプロセス共有キューと一時ファイルrenameで実行。1MB・1000履歴を上限とし、破損・欠落・保存失敗を空履歴と偽らない。開発サーバーは1つだけ起動し、JSON手編集・Git操作の前に停止する。

テストは `npm run test:local-demo`。ブラウザ試験では固定の `tests/fixtures/local-demo` を一時ディレクトリへコピーし、サーバー側の `MILIFE_LOCAL_DEMO_DIR` に指定する。テスト側も同じコピーを `MILIFE_LOCAL_DEMO_TEST_DIR` に指定する。APIが返す保存先のSHA-256指紋を更新前に照合し、不一致は試験を中断する。テストはこのコピーだけを初期化するため、実際の共有JSONを汚さない。通常利用で保存先を変える必要はない。

履歴保存のPOSTは表示中のrevisionを `If-Match` に指定する。Cookieの選択や履歴が変わっていれば保存前に409で拒否し、画面を再取得する。古いAI確認用GETは操作世代が変わった後には画面へ反映しない。

### 今回の実装判断と検証（2026-10-24）

- 作業環境の制約により既存チェックアウトで実装したため、作業ブランチの完全な分離はない。
- 単一要求のCookieでは後続の選択変更を検知できないため、AI応答後に再取得し、画面の操作世代も照合する。画面側にも整合性の維持を担わせる。
- 開発用選択を表示するログイン画面は全体をスクロールさせる。既存フォームの見切れを防ぐため、開発用画面ではスクロールが増える。
- Cookieは架空ユーザーの選択に限定する。本物の会員認証には置換が必要。
- 単一プロセス前提とし、手編集・Git操作前にサーバーを停止する。違反時の更新競合は対象外。
- 実OpenAI品質は未評価。趣味の関連性は実モデルで別途確認が必要。
- URLは `localhost` を利用する。既存NextのURL正規化制約により `127.0.0.1` 表記ではPOSTが拒否される場合がある。
- 本番DBのID・履歴の移行は別メンバーとの後続調整が必要。

最終レビューの重要指摘4件を修正。単体テスト95件、ブラウザテスト12件、型チェック、Lintを含むビルドが成功。遅延GET、別タブの保存先不一致、試験保存先の不一致は修正前の失敗と修正後の成功を確認。固定テストseedは稼働用JSONから分離した。共有JSONに試験による差分なし。未対応の軽微指摘なし。
