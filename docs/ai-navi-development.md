# AI未来ナビの開発状態

2026-10-24：履歴から趣味・テーマを発見する開発体験版へ変更。本番の本人認証・実履歴の保存は未接続。実APIの意味的な提案品質はキー設定後に確認する。

## 目的と表示

本人に好きなことや希望を説明させるのではなく、体験・閲覧・受講履歴の関連性から新しい楽しみを提案する。教材選定を主目的にはしない。

体験版には、希望を申告していない「写真の受講完了＋花飾りの閲覧」「写真の受講完了＋料理の閲覧」「履歴なし」の3ケースを用意した。切替は開発確認用で、本番の希望入力ではない。

提案は最大3件。「趣味・テーマ名」「なぜ合いそうか」「最初に試せること」「根拠となる履歴または人気」を表示する。関連教材は任意の補助案内。教材なしでもテーマを提案できる。

## 実装と境界

- `server/ai-navi/demo-data.ts`：固定サンプルの履歴と教材。履歴IDに閲覧・完了の種別を含め、個人名・他人の個別履歴はAIへ渡さない。
- `server/ai-navi/popularity.ts`：直近30日（開始境界を除く）のユニーク教材利用者を分母とし、利用率80%以上を人気とする。閲覧・完了・再読込の同一人は重複計上しない。実データなしは割合null。
- `server/ai-navi/candidates.ts`：教材の一次抽出。体験版は履歴だけを使い、申告した興味や目標は渡さない。
- `server/ai-navi/openai.ts`：Responses APIに構造化した履歴と教材を送り、テーマを生成する。store:false、自動再試行なし、20秒打切り。
- `server/ai-navi/output.ts`：テーマ・理由・最初の行動を検証。履歴根拠は渡した履歴ID、人気根拠は集計で人気の教材IDに限定する。閲覧を完了へ変えたID、未知の教材、重複テーマ、不正形式を拒否する。
- `server/ai-navi/demo-handler.ts`：固定ケースIDのみを受け付け、入力サイズ・Origin・ローカルHost・開発用有効化を確認する。60秒3回、同時1回。上流のエラー本文やAPIキーを画面に返さない。

履歴なしでは人気を入口と明示し、本人の体験を発見したと装わない。自由文の意味的な正しさや「好き」「習得」等の断定を構造検証だけで保証はできない。プロンプトで抑制し、実モデルで品質評価する。

## 起動手順

1. `.env.local` に `OPENAI_API_KEY` と `OPENAI_MODEL` を設定する。キーをチャットやGitに貼らない。モデルは利用アカウントで利用可能なResponses API・Structured Outputs対応IDを指定する。
2. `npm run dev:ai-navi` で起動し、`http://localhost:3002/ai-navi` を開く。
3. テスト用の履歴ケースを確認し「履歴からテーマを見つける」を押す。サンプルがOpenAIへ送信され、APIの従量料金が発生する。

専用コマンドは127.0.0.1:3002へ固定し、任意の起動引数を拒否する。通常のdev・dev:lan・本番では体験版は404。有効化フラグMILIFE_AI_NAVI_DEMOを他の起動環境や.envへ設定しない。

設定を変更したらサーバーを停止・再起動する。ビルド前にも開発サーバーを停止する。同じ.nextへ同時に開発・本番生成物を書き込むとキャッシュが不整合になる。

Next.js14のURL正規化による既知の制約があるため、127.0.0.1表記ではなくlocalhostで開く。開始済みOpenAI処理の課金取消は保証しない。回数制限は開発プロセス単位であり、再起動でリセットされる。

## 本番接続時の残作業

本人認証、本人の履歴のみの取得、同意・保持期限・削除、反応保存、入力版照合、変更・ログアウト後の応答破棄、応答時点の公開教材照合が必要。サーバー内部の型付きモジュールへ外部入力を直接渡さず、API側でJSON検証する。固定サンプルに対する参照検証を、本番の可変教材の再確認と混同しない。

## 2026-10-24：DB接続までの共有JSON保存

現在の開発体験版は固定ケース選択から、共有JSONの架空ユーザー選択へ移行した。`data/local-demo/materials.json` と `data/local-demo/users/*.json` をGitで共有できる。手順と形式は `data/local-demo/README.md` を参照。

専用起動後、`/login` の「開発用ユーザーでログイン」から3人の架空ユーザーを選ぶ。`/ai-navi` でも切替・ログアウトでき、教材を開くと閲覧、明示操作で受講完了を保存する。保存したJSONを元にAI入力と人気を作る。別タブの選択変更、履歴更新、ログアウト前の古い応答は表示しない。

人気の固定5人データは、このJSON接続経路では使用しない。全共有ユーザーの保存済み記録から直近30日の割合を計算する。初期JSONの日時は2026-10-24T00:00:00.000Zで、自動的に再日付しない。古くなれば集計対象外になる。

選択CookieはHttpOnly・SameSite=Laxで7日保持し、Gitに入れない。保存対象は架空データのみで、本番のログイン認証や権限保護ではない。登録体験とUnityの外見保存は既存のブラウザ保存のまま別機能として維持する。

ファイル更新はプロセス共有キューと一時ファイルrenameで実行。1MB・1000履歴を上限とし、破損・欠落・保存失敗を空履歴と偽らない。開発サーバーは1つだけ起動し、JSON手編集・Git操作の前に停止する。

テストは `npm run test:local-demo`。ブラウザ試験では共有データを一時ディレクトリへコピーし、サーバー側の `MILIFE_LOCAL_DEMO_DIR` に指定する。テスト側も同じコピーを `MILIFE_LOCAL_DEMO_TEST_DIR` に指定する。テストはこのコピーだけを初期化するため、実際の共有JSONを汚さない。通常利用で保存先を変える必要はない。
