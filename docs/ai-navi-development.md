# AI未来ナビの開発状態

2026-10-23：推薦コアを実装。実AI・利用者向け画面・本人認証・DB保存は未接続。

## 実装した処理

- `server/ai-navi/popularity.ts`：直近30日（開始時刻を除き終了時刻を含む）の公開教材の利用を集計。閲覧・完了を合わせたユニーク利用者が分母で、教材ごとの利用率80%以上を人気と判定する。割合は0〜1の小数。対象人数・期間とともに画面へ渡す。データなしは割合null。
- `server/ai-navi/candidates.ts`：本人の反応・関心や目標・閲覧受講履歴・人気から最大20件の公開教材候補を抽出する。キーワード一致による一次選択であり、AIによる意味理解や提案文生成ではない。反応撤回時は入力から取り除く。
- `server/ai-navi/output.ts`：AIが返す最大3件の教材ID・理由・次の学びを検証する。未知ID、重複、不正形式を拒否する。空配列は候補なし。未知の余分なフィールドは捨てる。

## 接続時の責務

このモジュールは外部公開APIではない。型付きのサーバー内部データを受け取る。外部入力には別途実行時検証が必要。

本人認証、本人だけのプロフィール・履歴取得、項目別のAI利用許可、反応の最新版選択と保存はAPI・保存基盤側で実装する。学習イベントのuserIdをブラウザから信頼しない。人気集計の全体イベントと、個別提案の本人イベントは分離する。他者のID・生の履歴はAIへ送らない。年齢・性別の利用は許可UIとともに後続実装で追加する。

候補抽出時とAI応答受信時の両方で公開状態を確認し、`validateSuggestions`のallowedIdsは「今回渡した候補ID」と「応答時点の公開教材ID」の積集合から作る。提案実行時の本人・入力版・許可設定と応答時点を照合し、変更やログアウト後の応答は破棄する。検証済み文章もHTMLとして解釈せずテキスト表示する。

実AIの失敗を固定の提案成功と偽らず、候補なし・未設定・通信失敗を区別する。教材を閲覧しただけで完了履歴を作らない。人気は実集計だけで表示し、開発サンプルはサンプルと明示する。

## 次の工程

利用者の希望によりOpenAI APIを使用する。APIキーはサーバー環境変数で管理し、チャットやGitへ書かない。接続先・モデル・タイムアウト・費用制御・利用説明と、認証・永続保存・画面の設計を具体化してから接続する。現時点で外部へデータは送信していない。

## 検証

`npm run test:ai-navi` でコアのテストを実行。`npm test` では既存の広場テストも実行する。tsxのIPCが制限される環境では純粋なユニットテストを `node --import tsx --test tests/ai-navi/*.test.ts` で実行できる。広場の通信テストにはローカルソケットの利用権限が必要。
