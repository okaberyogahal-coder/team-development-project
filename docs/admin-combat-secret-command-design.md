# 管理者用の隠し戦闘コマンド（設計案）

## 目的

戦闘モードを、許可された管理者だけが遊びとして起動できる隠し機能にする。一般ユーザー向けの操作説明やUIには表示しない。

## 管理者の判定

- `UNITY_COMBAT_ADMIN_EMAILS` にカンマ区切りで登録したメールアドレスだけを管理者として扱う。
- 照合は前後空白を除き、大文字小文字を区別しない。
- BetterAuthのユーザー情報で`emailVerified`がtrueであることも必須とする。
- サーバーは既存の認証Cookieを検証した後で許可フラグを返す。ユーザーIDやメールアドレスをUnityから送って権限判定する方式にはしない。
- 環境変数が未設定、未認証、停止済みアカウントの場合は許可しない。
- DBロールやマイグレーションは追加しない。

## 隠しコマンドと挙動

- Unityワールドにフォーカスがある状態で、`↑ ↑ ↓ ↓ ← → ← → B A` を順に入力すると戦闘状態を切り替える。
- 途中で別のキーを押したら、列の一致状態をリセットする。
- 一般ユーザーやゲストは同じ列を入力しても何も起きない。
- 従来のFキーは誰にも戦闘を起動しない。コマンドは画面内のヘルプや一般向け説明に表示しない。
- 認証ユーザーがログアウトする、別ユーザーへ切り替わる、管理者許可を失う場合は戦闘を停止する。

## 実装範囲

1. `/api/unity/session` がサーバー側の許可リストを照合し、認証済みユーザーにだけ `canUseCombat` を返す。
2. Unityのセッションブリッジが許可フラグを保持し、ゲストや失効時に必ずfalseへ戻す。
3. 戦闘入力をコナミコマンドに変更し、Fキーからは切り替わらないようにする。
4. 自動テストで未認証、一般ユーザー、許可管理者、権限失効後、Fキー無効を確認する。
5. WebGLをクリーンビルドし、ローカル配信物を更新する。

## 境界

戦闘はブラウザー内だけの演出で、サーバー状態・報酬・ユーザーデータを変更しない。そのため、この制御は遊び機能の表示制限として扱う。将来サーバー側の特典や操作を追加する場合は、各APIでも管理者権限を個別に検証する。

## 運用

本番と開発環境で`UNITY_COMBAT_ADMIN_EMAILS`を個別に設定する。値を指定しない環境では機能は無効になる。メールアドレスはクライアントへ返さず、許可フラグだけを渡す。
