# AI未来ナビ OpenAI開発体験版

2026-10-23。状態：設計・計画承認済み、開発体験版を実装。実APIの接続確認はキー設定後。

## 目的と合意

利用者はOpenAI APIを使い、まず開発用のサンプル教材で提案を確認する方式を選択した。既存の推薦コアを実AIへつなぎ、カメラ・生花などの関心と履歴が提案につながるかを試す。本番認証・DB・実利用者の履歴収集は別工程。

## Approaches

- 採用：開発体験版。サンプル教材・固定のサンプルプロフィールから始めるので、本番の保存基盤を待たず提案品質を試せる。
- 今回見送り：認証・永続保存から本番構成を作る。実履歴を使えるが範囲が大きく、AIの提案確認まで時間がかかる。

## 実装案（担当者の提案）

- `/ai-navi` に開発用の簡素な操作画面を追加する。サンプル利用者として「カメラが趣味・撮影教材を閲覧」「初めて・履歴なし」などを選び、明示操作で提案を実行する。サンプル教材と提案理由・次に学ぶことを確認できる。
- 実データの入力・会員登録とは接続せず、サンプルであることを表示する。年齢・性別の利用と設定は本番の許可UIで扱い、体験版で実属性を収集しない。
- 開発専用の提案APIはサーバー固定のサンプルIDだけを受け取り、サーバーで候補を作る。本文をサイズ制限し、未知ID・Origin不一致を拒否する。個人の生データや任意URLを受け取らない。
- `NODE_ENV=development` のみ有効とし、それ以外では画面・APIを404にする。ループバック接続だけを受け付け、公開サイトへ費用の発生する匿名APIを出さない。1回ずつ実行、1プロセスで60秒3回の上限を設ける。
- OpenAI Responses APIのStructured Outputsで `suggestions`（最大3件、教材ID・理由・次の学び）を生成し、コアの検証関数でもチェックする。候補外IDを拒否する。`store: false` とし、入力やAPIキーをログに出さない。
- `OPENAI_API_KEY` と `OPENAI_MODEL` をサーバー環境変数で設定する。モデルは環境で選べるようにし、未設定時は設定不足として案内する。キーをブラウザへ返さない。
- APIは20秒で打ち切り、自動再試行しない。APIキーなし・候補なし・上限到達・タイムアウト・OpenAI失敗・不正応答を区別する。外部エラー本文・秘密情報は画面へ返さない。
- サンプルの人気集計は架空の実績から作り、対象人数・割合・期間と「サンプル」を表示する。本番の利用率と表現しない。

## 検証と完了条件

キーなし、開発環境以外、未知ID、Origin不一致、上限、タイムアウト、不正ID・JSON、OpenAI拒否をテストする。通信境界のみ偽の応答を使い、候補作成・リクエスト構築・出力検証は実処理を通す。型チェック・既存テスト・ビルド・操作画面を確認する。実APIは利用者がキーを設定した後に確認し、未接続を接続成功と報告しない。

## 公式API資料

[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Responses移行ガイド](https://developers.openai.com/api/docs/guides/migrate-to-responses)を2026-10-23に確認した。

## 実装時の補強（2026-10-23）

Host/Origin検証だけではLANからの直接HTTPを排除できないため、専用の `npm run dev:ai-navi` で127.0.0.1:3002へ固定して起動する。専用コマンドだけで有効化フラグを設定し、追加のhost等の引数を拒否する。通常のdev・dev:lan・本番起動では画面とAPIを無効にする。
