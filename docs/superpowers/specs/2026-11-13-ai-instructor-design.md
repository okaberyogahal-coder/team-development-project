# 教材伴走型AI講師：初期導入設計

## 目的と合意済みの方向

みらいふの利用者が教材を学びながら疑問を解消し、確認問題と復習を通じて学習を続けられるようにする。利用者は教材伴走型を軸にした具体的な導入設計への進行を了承した。この文書の実装範囲・初期設定は提案であり、文書承認後に実装計画を作成する。

## 検討した方式

1. 質問対応型：小さく導入できるが、教材の進行や理解度確認は別に必要。
2. 教材伴走型（選択）：教材の説明・質問・確認問題を一つの学習体験として扱える。根拠となる教材本文の整備が必要。
3. 対話授業型：音声やアバターで授業を進める。音声処理・会話制御などが増えるため後続段階にする。

## 現状

- Next.js 16.4.2 / React 19.3.1。実装前に `node_modules/next/dist/docs/` の該当ガイドを読む。
- `server/ai-navi/openai.ts` にサーバーからのAI接続、応答検証、タイムアウト処理がある。質問応答への流用は設計を分け、未来ナビの推薦形式は変更しない。
- `app/ai-navi` と関連APIは開発環境・ローカル限定。ローカルセッションと利用制限の仕組みがある。本番認証と同一視しない。
- `data/local-demo/materials.json` は紹介文と分類が中心で、授業の根拠となる本文・設問はない。
- DBには教材と受講進捗のモデルがあるが、AI講師の会話・教材本文・小テストの保存モデルはない。
- 現行の未来ナビは履歴から趣味やテーマを発見する機能で、教材リンクは補助的。トップページの紹介表示も含め、本番の学習導線が接続済みとは扱わない。

## 初期実装の範囲（提案）

ローカル検証版を最初の成果物とする。本番公開やDB変更を含めず、教材本文を読む・AIに質問する・確認問題に答える・復習する一連の体験を検証する。

- 初期教材は既存のサンプル「自然光と背景ぼけの基本」を採用する。本文は新規作成するサンプルであることを明記する。教材担当者の監修・利用権確認を本番移行条件にする。
- 教材には安定した節ID、本文、版、学習目標、節に対応する三択問題3問と解説を持たせる。既存教材一覧とはIDで関連付ける。
- 「やさしく説明」「具体例」「質問」を文字チャットで受け付ける。会話履歴の範囲内で追加質問を理解する。
- 確認問題は承認対象の固定問題とし、正誤判定・点数はサーバーの規則で決める。正答を回答前にクライアントへ送らない。AIが判定や点数を上書きしない。
- 間違えた問題の対応節に戻って復習できる。全問終了は「確認問題を終了」と表示し、習得の保証や正式な受講完了記録とはしない。
- 次の学習は当該教材の復習と、実在する公開サンプル教材への案内に限る。存在しない教材や受講可能性を作らない。

音声・アバター、教材アップロード、自動文字起こし、検索基盤、履歴の永続保存、正式な成績管理、推薦ロジックの変更は初期範囲外。

## 学習と回答の規則

開始時に教材と学習目標を示し、本人の操作で説明や質問を実行する。自動でAI要求を連続実行しない。

サーバーが教材IDと版から本文を取得し、AIへ本文・現在の節・制限内の会話だけを渡す。教材や会話内の命令でシステム規則を変更させない。氏名・メール・年齢・他教材の履歴は追加しない。利用前に教材本文と質問がAI提供先へ送られる旨を伝える。

回答は日本語で短く、専門語には説明を添える。本文で裏付けられる説明や、本文から導ける例に限定する。回答に根拠節IDを付け、参照先を開けるようにする。サーバーはIDの実在を検証するが、これだけで回答内容の正確性を保証したとは扱わない。教材で確認できない質問にはその旨を伝え、関連節や教材に沿う質問を案内する。自由な一般知識回答は初期版では行わない。

AI未設定・通信失敗・タイムアウト・回答形式不正・利用上限・根拠なしを区別する。失敗時にも本文と確認問題は使える。固定文やサンプル応答を実AIの回答と表示しない。

## セッション・接続・利用制限（提案）

- ローカル検証用の既存ログインを使用し、開発環境・ローカルホスト・専用有効化設定・同一オリジンを要求する。教材IDや本文のブラウザ入力を信用しない。
- 教材版・所有セッション・会話の連番をサーバーで管理する。任意の会話履歴をクライアントから注入できないようにする。
- 会話はプロセスメモリにのみ保持し、無操作30分・ログアウト・再開始で失効する。再起動で消えることを明示する。本人切替・教材変更後の古い応答は表示しない。
- 初期値は質問1件1,000文字、会話は直近10メッセージ（省略前の文脈は保持しない旨を表示）、1セッション20回、1分3回、同時要求1件、教材本文12,000文字、回答出力1,200トークン、タイムアウト20秒。保持中会話は最大100件、超過時は新規開始を制限する。
- APIキーとモデル設定はサーバーのみ。既存接続方式を参考に専用アダプターを設ける。提供先は既存と同じOpenAIを提案するが、モデルは実装時に公式資料と利用可能な設定を確認して選ぶ。
- ローカル版は単一プロセスで検証する。分散環境の制限・金額上限・本番保存方針は本番移行時に設計し、試験版の回数制限を費用保証とは扱わない。

## 構成と実装者に委ねる事項

教材データ・会話サービス・AIアダプター・API・学習用画面を分離する。未来ナビの既存推薦テストを維持する。具体的なファイル名、データ型、画面配置、視覚表現は実装計画で決める。既存画面の日本語・操作スタイルを引き継ぎ、キーボード操作、読み込み状態、エラー通知、スマートフォンでの利用を考慮する。

初期版の入口はローカル検証用とする。未来ナビから教材への連携は、教材伴走体験を確認した次の段階で設ける。

## 受け入れ条件と検証

1. 対象教材の本文を読み、根拠節へ戻れる説明・質問回答を実AIで試せる。未設定時は設定不足を明示する。
2. 教材外の質問への応答、実在しない根拠IDの拒否、本文・質問内の命令への耐性を確認する。
3. 固定問題3問の正誤判定と復習先が一致する。回答前のAPIデータに正答を含めない。
4. 未認証、異なる所有者、非ローカル、無効な教材、入力超過、上限到達、二重送信、期限切れを拒否する。
5. ログアウト・本人切替・再開始・教材版変更中の古い応答を破棄する。
6. AIの失敗時も本文と確認問題を使える。会話をアプリの永続ストアや通常ログに記録しない。
7. 型チェック、関連ユニットテスト、ブラウザでの一連の学習操作、既存AI未来ナビへの回帰確認を行う。実AIの手動確認とモック試験の結果を区別して報告する。

## 本番移行までの順序

1. この設計の確認後、実装計画を作成する。
2. ローカル版を実装し、教材の正確性・質問への回答・操作性を確認する。
3. 教材監修、本番認証と権限、保持・削除方針、運用の利用上限・費用管理、実教材への接続を整備する。
4. 限定公開で回答の教材整合性、疑問を解消できた割合、学習継続を評価し、本番導入範囲を決める。評価のための質問本文収集は別途合意する。

## 承認対象

教材伴走型・文字チャット、サンプル教材1本、ローカル検証から開始する範囲、固定確認問題、会話を永続保存しない方針を確認する。教材選定・制限値・提供先は上記の提案値であり、変更可能。この文書はAI講師の実装や公開完了を意味しない。
