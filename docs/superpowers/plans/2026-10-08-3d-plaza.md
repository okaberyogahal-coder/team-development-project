# 3D Plaza Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if the user chooses delegation. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 現在の交流広場を、丸い造形とパステル色の見下ろし3Dへ変更する。

**Architecture:** WorldMapの入力・移動インターフェースを維持して、表示をクライアント専用Three.jsキャンバスへ置き換える。位置同期と通話は既存の仕組みを利用する。3Dに失敗した場合は既存2D表示へ切り替える。

**Tech Stack:** Next.js 14、React 18、TypeScript、Three.js、Node test runner、Playwright。

**Spec:** `docs/superpowers/specs/2026-10-08-3d-plaza-design.md`

## Global Constraints

- PCブラウザーを初版の対象とする。
- 既存の1000×700の領域、速度、facing、参加者ID、部屋IDを維持し、通信メッセージを変更しない。
- カメラの回転・追尾・ズーム操作は初版には加えない。
- ジャンプ、服装編集、自由カメラ、スマートフォン専用操作は後続の機能とする。
- 既存ゲームの素材は使わない。
- 既存変更の `server/plaza/calls.ts`、`server/plaza/index.ts`、`tests/plaza/calls.test.ts` を変更・ステージしない。
- LiveKitの設定作成・実通話検証・公開環境への配置は実装範囲に含めない。
- 50人表示はMacのChrome、1440×1000で30秒間測定し、平均30fps以上を目標にする。

## Review Focus

- 部屋移動の直後に旧部屋の参加者や補間状態が残らない（Task 1、4）。
- 入力欄、キー長押し、接続待ちで操作が暴走しない（Task 4）。
- WebGL初期化失敗とコンテキスト喪失でも2Dと部屋選択を利用できる（Task 4）。
- 縦横比変更時に入口と名前が3D表示に追従する（Task 3、5）。
- 退出・再入場で描画ループとイベントが増殖しない（Task 3、5）。

- `app/components/plaza/useWorldMovement.ts`：既存キー操作と停止処理。
- `app/components/plaza/world3d/coordinates.ts`：座標変換・位置補間。
- `app/components/plaza/world3d/assets.ts`：共有形状・材質の生成と解放。
- `app/components/plaza/world3d/scenery.ts`：広場、室内、入口座標。

- `app/components/plaza/world3d/runtime.ts`：カメラ、描画ループ、参加者更新、資源解放。
- `app/components/plaza/world3d/WorldCanvas.tsx`：Reactとruntimeの接続、HTMLラベル。
- `app/plaza/plaza.css`：キャンバス、投影ラベル、障害案内。
- `tests/plaza/world3d.test.ts`：座標・補間・向き・資源解放。
- `tests/browser/plaza.spec.ts`：既存試験の3D対応。

- `docs/plaza-testing.md`：起動方法と実測結果。

### Task 1: 座標と補間の基盤

**Interfaces:** `toWorld(p: Position): {x:number;y:number;z:number}`、`interpolatePosition(current: Position,target: Position,dtMs:number): Position`、`facingToRotation(facing:number): number`。

- [x] `shared/plaza/types.ts`、サーバーのfacing計算、承認済み設計書を読む。
- [x] `tests/plaza/world3d.test.ts` に、中央 `{x:500,y:350}` → `{x:0,y:0,z:0}`、端点 `{x:0,y:0}` → `{x:-10,y:0,z:-7}`、負のdtで不動、100ms以上でtargetに到達、上下左右の向きの試験を書く。向きの期待値はサーバーのfacing規約に合わせる。
- [x] `npx tsx --test tests/plaza/world3d.test.ts` を実行し、未実装による失敗を確認する。
- [x] `coordinates.ts` を作成する。座標は1/50に縮小して中央を原点とし、補間係数は `min(max(dtMs,0)/100,1)` にする。
- [x] 同コマンドで成功を確認し、Task 1のファイルのみコミットする。

### Task 2: 風景とキャラクター

**Interfaces:** `createAssets(): {geometry(name:string): BufferGeometry;material(color:string): MeshStandardMaterial;dispose():void}`、`createScenery(roomId:RoomId,assets:ReturnType<typeof createAssets>): {group:Group;doors:Array<{roomId:RoomId;position:Vector3}>}`、`createAvatar(avatar:AvatarId,self:boolean,assets:ReturnType<typeof createAssets>): {group:Group;animate(distance:number,time:number):void;setConnected(connected:boolean):void}`。

- [x] npmレジストリで `three` と `@types/three` の版を確認し、対応する版を固定して依存を追加する。React向け追加フレームワークは導入しない。package-lockを更新する。
- [x] assetsの再利用と二重dispose防止、全5室の入口先、全5色のアバター生成を `world3d.test.ts` に追加する。初期未実装で試験を実行して失敗を確認する。
- [x] `assets.ts`、`scenery.ts`、`avatar.ts` を実装する。木の配置はWALLSと整合させる。建物の入口は既存housesの座標を変換する。室内は奥壁のみとし、ロビーへの出口を置く。
- [x] `npx tsx --test tests/plaza/world3d.test.ts` と `npx tsc --noEmit --incremental false` の成功を確認する。
- [x] 依存とTask 2のファイルのみコミットする。

### Task 3: 描画と投影ラベル

**Interfaces:** `createRuntime(host:HTMLElement,roomId:RoomId,onFrame:(frame:Frame)=>void,onFailure:()=>void): {update(participants:Participant[],selfId:string):void;dispose():void}`。`Frame` は `{people:Array<{id:string;x:number;y:number;worldX:number;worldY:number}>,doors:Array<{roomId:RoomId;x:number;y:number}>,fps:number}`。x/yはhost内CSSピクセル、worldX/worldYは補間された元の1000×700座標。

- [x] `WorldCanvas` に `roomId,participants,selfId,onRoom,disabled,onFailure` を渡すブラウザー試験を用意し、canvasと投影ラベルがない状態で失敗を確認する。
- [x] `runtime.ts` を実装する。カメラは `(0,22,18)` から原点を見る。床と建物を含む範囲をサイズに合わせて収め、ピクセル比上限を1.5にする。単一setAnimationLoop、ResizeObserver、visibilitychange、webglcontextlostを管理する。
- [x] `WorldCanvas.tsx` を実装する。参加者IDでモデルを再利用し、更新時に退室済みモデルを外す。部屋変更はruntimeを再生成して補間をリセットする。名前はDOM参照で投影位置を更新し、入口はHTML buttonとする。ラベルに `data-world-x` と `data-world-y` を出し、位置同期をブラウザー試験で観測できるようにする。
- [x] 停止時は `setAnimationLoop(null)`、observer切断、イベント解除、共有資源とrendererのdisposeを行う。初期化途中の失敗も同じ解放経路にする。
- [x] ブラウザーで広場と4室を描画し、ウィンドウ縮小後も入口が建物に追従することと、部屋移動で旧参加者ラベルが残らないことを試験する。
- [x] 型検査と対象ブラウザー試験に成功したらTask 3のみコミットする。

### Task 4: 既存画面への統合と2D切り替え

**Interfaces:** 既存 `WorldMap` のpropsと `PlazaClient` の呼び出しを維持。`useWorldMovement(onMove:(d:Direction)=>void,disabled:boolean,roomId:RoomId):void` を3Dと2Dで共用する。

- [x] `WorldMap2D.tsx` に既存描画を退避し、入力処理を `useWorldMovement.ts` に移す。1つの表示で入力hookを1度だけ呼び出す。
- [x] 既存のブラウザー試験の `.plaza-person.is-self` を3Dラベルにも維持する。移動前後の `data-world-x` を比較する試験に更新する。
- [x] `plaza-3d.spec.ts` に初期化失敗の試験を書く。addInitScriptでHTMLCanvasElement.getContextのwebgl/webgl2のみnullにし、障害案内と「2Dで表示」ボタン、切り替え後のSVGと部屋移動を確認する。WebGLコンテキスト喪失も別に試験する。未実装時の失敗を確認する。
- [x] `WorldMap` でssr:falseのdynamic importを使い、ロード案内、障害案内、2Dへの切り替えを実装する。`plaza.css` でcanvasとoverlayの重ね方を設定し、入口buttonのみポインター操作を有効にする。
- [x] 接続待ち中、キー長押し、入力欄フォーカス、window blur時に移動が停止する試験を追加する。左右移動で画面上のラベルも対応する方向へ動くことを確認する。
- [x] `npm test`、型検査、全ブラウザー試験で成功を確認してTask 4のみコミットする。

### Task 5: 見た目・負荷・最終確認

**Interfaces:** `createRuntime` のFrame.fpsを利用し、公開UIに計測情報は追加しない。

- [x] 2ブラウザーで相互の名前と座標変化を確認し、同室・別室・戻る・退出の一連の操作を試験する。再入場を5回繰り返し、canvasが常に1個、pageerrorが0件であることを確認する。
- [x] 広場と4室の1440×1000スクリーンショットを保存し、建物、アバター、名前、入口、通話パネルの表示を目視確認する。1024×768でも入口を操作する。
- [x] テスト専用のWebSocketメッセージ置換で50人の移動stateを生成する。1440×1000、30秒間、フレーム間隔から平均fpsを計測して記録する。30fps未満なら影と形状を軽量化し再測定する。
- [x] `npm test` と `npx tsc --noEmit --incremental false` を実行する。本番ビルドは開発サーバーと同じ.nextに出力しないよう別作業コピーまたは停止後に `npm run build` を実行する。
- [x] `npm run test:browser` とWebGL障害試験を実行する。実通話は未検証と記録し、通話未設定時の案内と部屋移動の動作を確認する。
- [x] `docs/plaza-testing.md` に実施条件、実測値、3Dと2Dの切り替え方法を記録する。
- [x] 差分に既存の通話変更が混ざっていないことを確認し、全体レビュー後に3D化の対象ファイルだけコミットする。GitHubへのpushはユーザーが求めた場合に行う。
