# 3D広場の検証・判断記録

## 結果

3D化をローカルのmainへ統合した。既存の通話設定3ファイルと編集中のrequirements.mdは、統合前後のSHA-256比較で内容を保持していることを確認した。並行して作成された他の要件書にも変更を加えていない。

隔離した作業環境では単体・サーバーテスト43件、型検査、本番ビルド、ブラウザーの11項目を確認した。元の環境では既存のLiveKitタイムアウト試験が加わり、単体・サーバーテスト44件が成功した。通常URLでの初回確認は依存追加前の開発サーバーのエラーが残ったため1件時間切れになったが、インストール完了後にその1件を再実行し成功した。残り10件も成功しており、計11項目を確認した。

50人の合成アバター表示は、1440×1000のMacのChromeで30秒間、約60fpsだった。描画完了後の投影位置更新を計数した値であり、実際の50台接続・50人の通話性能ではない。

独立したレビュー担当が設計書、計画、実装、周辺の接続処理を確認し、修正すべき問題・保留した軽微な問題はともに0件。3D単体テスト7件も独立して実行し成功した。

## 実装中の判断

1. 依存環境は独立してインストールした。稼働中アプリの依存を途中で変えないためで、追加のインストール時間がかかった。
2. 作業単位の単体試験では `node --import tsx --test` を使った。制限環境でtsx CLIのIPCが拒否されたためで、同じファイル・同じNodeテストランナーを使う。最終確認では通常の `npm test` も実行した。
3. 3D描画の工程で実際のWorldMapに組み込んだ。使い捨ての試験ページを増やさず実際の入室フローを確認するためで、2D切り替えと入力の分離は次の工程で行った。
4. 隔離環境の画面確認には3102と `PLAZA_TEST_URL` を使った。元の3002の開発サーバーと検証を混在させないためで、接続OriginとLAN参加も対応するポートで確認した。最後に通常の3002でも確認した。
5. 描画速度はUIへ計測情報を出さず、テスト側のMutationObserverで測った。実際の描画完了を確認するためで、GPU処理の個別時間や実通話性能を計測するものではない。
6. 実際のLiveKit音声・映像と遠隔通話容量の確認は、承認済みの3D化の範囲外とした。既存インターフェースと通話パネルを保ったが、実通話の受入試験は別途必要。

GitHubへのpushは実施していない。使い方と詳細な条件は `docs/plaza-testing.md` を参照。
