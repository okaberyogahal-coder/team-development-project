## レビューと修正

独立レビューで、別タブのログイン変更・画面離脱後に、遅れて到着したセッション確認結果で完成値を書き込める競合を指摘された。2件のブラウザ再現テストで修正前の失敗を確認し、認証・ライフサイクル世代で保留中の保存を無効にした。認証変更後は古い画面から下書きも更新しない。修正後の2件と上記43件は通過した。

UnityのJsonUtilityがnullの入れ子を空インスタンスとして扱うため、新旧外見の排他判定の前に空のプレースホルダーを除去する。再現テストで失敗→修正後40件成功を確認した。ログアウト後の診断値もモデルIDの有無で判定する。

## 範囲外として残る既存スモーク失敗

広い `npm run test:smoke` は33件成功・8件失敗。全スモーク成功とは扱わない。

- `auth-flow.spec.ts` の5件: マイページ390pxの横幅条件（既存CSSはmin-width1000px）、分野と強みに同じ文字がある場合の広いテキスト件数判定など、既存マイページの表示前提。
- `auth.spec.ts` の3件: 既存登録フォームの入力遷移・PCでの全操作ボタン可視条件。

今回の外見置き換えで認証・登録画面の製品コードは変更していない。これらを成功と見せるためのスキップや検証の緩和はしていない。新しいログイン必須の `/avatar` と整合しない旧アバターUI専用試験は、新UIの操作・ブランド・表示幅の試験へ更新した。

共有DBへの変更、mainへのマージ、リモートへのプッシュは行っていない。テストは専用ローカルDBで実施し、検証後にそのコンテナを削除する。
