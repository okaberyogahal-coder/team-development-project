# ミライフ 3D広場　グラフィック大改修レポート（2026-10-30）

対象：10/15 版の Unity プロジェクト（FutureCity_Unity_1of2 / 2of2）
目標：原神のような高品質なアニメ調 3D に近づけつつ、ミライフ独自の「2127年の、緑と白の学びの庭」の世界観を保つ。
あわせて、届いていなかった **戦闘モード** を最新版に組み込み直した。

---

## 1. まとめ

| 区分 | 改修前 | 改修後 |

## 2. 改修前の分析（安っぽく見えた原因）

改修前のプロジェクトを実際に動かして描いた画像（比較画像の左側）から、次の 7 点を原因と判断した。

1. **形が単純**：ベンチ・花壇・壁・交流室・家具・人物が、コードで並べた箱・円柱・球。角の丸めも小さく、輪郭がまっすぐで情報量が少ない。
2. **質感と形の不一致**：写真のテクスチャ（石・木・布）を単純な形に貼っているため、「本物の素材なのに形が粗い」ちぐはぐさが目立つ。
3. **背景と前景の不一致**：まわりの景色が 360°写真で、3D の広場と光・空気感・解像感がそろわない。写真は動かず、奥行きも出ない。
4. **植物の作り**：葉の板（カード）の縁が透けてざらつき、裏側が暗くなる。草は交差した板が星形に見え、地面の色が暗い緑で単調。
5. **光と色**：影が灰色にくすみ、白い石畳が白飛びしやすい。配色が淡く、どこを見ればよいかがはっきりしない。
6. **人物**：顔がなく、体は球と円柱。画面の中心にいるアバターが最も「安っぽさ」を感じさせていた。
7. **統一感**：実写の素材、CG の建物、写真の背景が混ざり、絵としての方向性がそろっていない。

## 3. 方針

- **描き方を一本化**：実写風をやめ、アニメ調のトゥーン描画で全体をそろえる。原神に見られる要素（やわらかい陰影、色のある影、リムライト、人物の輪郭線、絵画的な空と雲、空気遠近）を取り入れつつ、建物・配色・小物は **ミライフ独自**（白い曲面の建築・金のアクセント・パステルの石畳・ガラス・屋上緑化・光る輪の彫刻）で作る。原神の素材・形・キャラクターは使っていない。
- **シェーダーは自作（MiraiToon）**：URP 用に HLSL で書いた。アセットストアの購入や外部ライセンスが不要で、コードで作る世界と同じ考え方（頂点色の AO・風の効き）をそのまま使える。
- **モデルは Blender で作る（スクリプトで再現可能）**：Blender の Python スクリプトで作り、ミライフ独自の形式（MMSH、`.bytes`）で書き出して、Play 時に `Resources` から読み込む。シーンを作る流れ（Create Scene → Play）を変えずに済み、取り込み設定の手間もない。スクリプトは `tools/` に同梱したので、形の調整・作り直しができる。
- **既存の仕組みは変えない**：歩行・視点・UI・画面・データ・地図の配置・スクリプトの公開部分（クラス名・部品名・関節の位置の考え方）はそのまま。アニメ調の部分は「アニメ調のときだけ」切りかわる作りにし、Inspector の **Anime Style** をオフにすると従来の実写風にもどる。
- **使わなかったもの**：Terrain（広場は平らで、遠景の丘は専用のメッシュの方が軽い）、Shader Graph（手書きの HLSL の方が細かく制御でき、URP の版の違いにも強い）。必要になれば Shader Graph 版を作ることもできる。

## 4. 実装した内容

### 4.1 シェーダー（`Assets/FutureCity/Resources/FutureCityShaders/`）

| シェーダー | 用途・特徴 |
|---|---|
| MiraiToon/Lit | 建物・地面・小物。2 段のやわらかい陰影（境目の位置・やわらかさ）、影の色（青紫寄り）、影の縁の締め、頂点 AO、様式化したハイライト、リムライト（日なたは光の色・日かげは空の色）、筆のむら（ノイズ）、空気遠近 |
| MiraiToon/LitOutline | 上に加えて輪郭線（画面上の太さで一定、色は材質の色を濃くしたもの）。人物・髪・服に使用 |
| MiraiToon/Foliage | 葉・花。切り抜き、両面、透過光（逆光で黄緑に光る）、風のゆれ |
| MiraiToon/Grass | 草。根元から先へのグラデーション、風、プレイヤーの足もとで押し分け |
| MiraiToon/Water | 噴水・池・湖。浅い所と深い所の色、流れる波、縁の白い泡、空と太陽の映り込み |
| MiraiToon/Glass | ガラス。縁が明るいフレネル、斜めの光の筋 |
| MiraiToon/Sky | 空。天頂〜地平線のグラデーション、太陽のかすみ、積雲（陰影つきのテクスチャ） |
| MiraiToon/Effect | 光の効果（ビーム・火花・シールドの輪）。加算合成 |

- 共通の計算は `MiraiToonCore.hlsl` に集約。太陽・空・環境光・霧・風の値は `MiraiAtmosphere` が毎フレーム全シェーダーへ渡す（Inspector で調整でき、プレイ中に変えるとすぐ反映）。
- シェーダーは `Resources` フォルダに置いたので、ビルドしたアプリにも必ず含まれる。

### 4.2 光・空・遠景

- 太陽：高さ 41°・方位 124°（南東）、少し暖かい白。影はソフトシャドウを少し締めてアニメ調の線に近づける。
- 環境光：上（空色）・横・下（地面の照り返し）の 3 色。影の側が灰色にならず、明るく色が残る。
- 空気遠近：距離と高さで薄くなる霧。広場の近く（30m 以内）はくっきり、遠くの丘・塔は空の色に溶けて奥行きが出る。
- 遠景（`MiraiSkyline`）：湖の向こうの緑の丘（半径 820〜2600m）、さらに遠い山なみ、白とガラスの未来の塔 6 種類の群れ、円盤の展望塔。空の積雲は 4096×1024 のテクスチャ（陰影の情報入り）。

### 4.3 中央広場（`MiraiPlaza`、モデルは `Resources/FutureCityModels/`）

噴水（2 段の水盤・金の帯）、輪の彫刻（3 本の輪がゆっくり回り、中央の光る球）、円に沿った曲面のベンチ 8 脚（白い石の脚・木の座面）、細身の街灯、丸い植木鉢 16 個と低木、角の丸い花壇（通路の切れ目つき）、4 つの入口のアーチ（機能の色の帯と紋章・灯り）と案内端末、南の「ようこそ」の大アーチ、パステルの石畳（同心円の帯と石の継ぎ目）、空中回廊の柱。

### 4.4 植物

- 木：中央の大きなかたまり＋まわりの小さなかたまり。法線を「かたまりの外向き」と「樹冠全体の外向き」で混ぜ、かたまりごとにやわらかい陰影が出る。内側ほど暗く（頂点 AO）、外側ほど風でゆれる。
- 桜・糸杉・低木・花畑・藤の花房も同じ考え方で作り直し。
- 草：芝生の上（1m のマス目で判定）にだけ、GPU インスタンシングで密に生やす。40m より遠くは描かず、30〜40m で徐々に短くして消す。
- 生け垣：四角い箱をやめ、重なり合うかたまりの連なり＋表面の葉。上の線がゆるく波打つ。

### 4.5 人物（`PersonFactory`、モデル `Chr*.bytes`）

- 部品：胴（上着）・縁どり（立ち襟・前立て・裾の帯。人ごとに色が変わる）・腰・太もも・すね・靴・袖・手・頭（首と耳）・顔（白目・ひとみ・瞳孔・まつげ・目の光・まゆ・口）・髪（短め・ボブ・ポニーテール・長め・おだんご）・めがね。
- 顔の色分け：肌・ひとみ・髪・服・ズボン・靴・縁どりの色を人ごとに変える（名前から決まる）。ほお紅と髪の「つやの輪」は頂点色で描いた。
- 子どもは頭を少し大きく（アニメの頭身）。ご年配の方は白髪・灰色の髪で、おだんご・短め・ボブ。
- 関節の名前・考え方は従来と同じ（LegL/LegR・ArmL/ArmR・Head）。**ひざ（Knee）を追加**し、座ると自然にひざが曲がり、歩くときも振り出す脚のひざが曲がる。服の色替え（入場画面のアバターの色）もそのまま使える。

### 4.6 4 つの交流室と庭

- 交流室（`RoomPavilion`）：角の丸い平面、白い腰壁＋大きなガラス＋縦の細い枠、部屋の色の帯（学び＝青・カフェ＝橙・経験共有＝桃・趣味＝緑）、張り出した屋根（木の軒裏・金の線）、屋上緑化と植え込み、入口のひさしと細い柱、看板（色の面と金の紋章）、天井の丸い灯り。部屋の位置・広さ・入口・入室の判定は従来と同じ。
- 家具：カフェのテーブルといす（布張り）・カウンター（コーヒーマシン・ショーケース）、学びの部屋の机と大きなボード、経験共有の部屋の曲面のソファと丸いローテーブル、趣味の部屋の作業台・棚と色とりどりの箱・イーゼル。
- 庭：まっすぐな庭のベンチ、パラソル（色の布）、藤棚（白い柱と弧を描く木の梁）、家庭菜園の木の花壇、公園のパーゴラ・カフェのテーブル（座っている人の位置はそのまま）、湖の船（流線形の船体とガラスの客室）。

### 4.7 ポストエフェクト（`PostFXSetup`）

Bloom（光る所がやわらかくにじむ）、トーンマッピング（Neutral：色相を保つ）、色調整（少しだけ明るく・鮮やかに）、ホワイトバランス、シャドウ／ミッドトーン／ハイライト、周辺減光（弱め）。アンチエイリアスは MSAA 4x＋SMAA（アニメ調の細い輪郭線は TAA よりこちらがくっきり）。

### 4.8 戦闘モード（`Runtime/Systems/CombatSystem.cs`）

| 操作 | 内容 |
|---|---|
| **F** | 戦闘モードの切りかえ（切りかえ音とお知らせ。腕の端末が光る） |
| **左クリック** | 画面中央の照準へ光のビーム（白い芯＋水色の光、手もとの光、当たった所の火花） |
| **右クリック（押している間）** | ねらう：肩ごしの視点に寄ってズーム、腕を照準の方へ。歩く速さは少し遅く |
| **E** | パンチ（目の前・1.6m 以内の人） |
| **Enter** | 話しかける・入室する・入口をひらく（戦闘モード中も使える。E はパンチなので） |

- 戦闘モード中は、視点が肩ごし（右肩）になり、体はいつも照準の方を向く。上方向もねらえる。
- 戦闘モード中は「クリックで歩く・話しかける」を止める（左クリックはビーム）。W A S D で歩ける。
- 広場の人は「パーソナルシールド」に守られている設定：当たると **シールドの輪**（六角形の模様）が光る。1 回目はよろけ、続けて当たる・パンチされると倒れ、しばらくして起き上がり、元の場所・向きにもどる（歩く人はその場からまた歩きだす）。**座っている人は身をすくめるだけ**。血などの表現はない。
- 効果音（ビーム・シールド・着弾・風切り・パンチ・切りかえ）は、その場でプログラムで合成する（音のファイル・外部素材なし）。
- ヘルプ画面と、戦闘モード中の画面上部に操作の案内を表示。Inspector の **Combat Mode** をオフにすると機能ごと無効。

### 4.9 互換性

- 変えていないもの：移動・視点・UI・画面とデータ・地図の配置・入室や入口の判定・デモ人物・未来ナビ・予約の規則。
- 公開している部品名（Suit・ArmL/Sleeve・Head など）・関節・当たり判定・メソッドは従来どおり。
- Inspector の **Anime Style** をオフにすると、人物・交流室・広場の小物も含めて従来の実写風にもどる（両方のコードが残っている）。

## 5. 検証（どう確かめたか）

この作業環境では Unity エディタ本体を動かせないため、次の方法で確かめた。**Unity 上での実際の見た目と動作速度は、お手元での確認が必要**です（手順は `docs/Unityでの確認手順_2026-10-30.md`）。

| 確認 | 方法 | 結果 |
|---|---|---|
| C# のコンパイル | Unity の API に合わせた代替ライブラリで、3 通りの設定（URP＋新 Input System／URP＋旧 Input／Built-in）とエディタ用コードをコンパイル | エラー 0・警告 0 |
| 実際の生成処理 | `FutureCityBootstrap` を代替の実行環境でそのまま動かし、できあがったシーン（物体・材質・光・空・カメラ・ポストエフェクト）を書き出す | 例外 0（アニメ調・実写風の両方） |
| 見た目 | 書き出したシーンを、MiraiToon と**同じシェーダーの計算**（MiraiToonCore.hlsl を共用）で描くプレビューで描画 | 比較画像のとおり（Unity の画面そのものではないので、細部は異なることがあります） |
| シェーダー | URP 17.4（Unity 6000.4）と URP の最新開発版のシェーダーライブラリと一緒に、glslang で Vulkan・D3D11 の両方をコンパイル（各キーワードの組み合わせ） | 全 8 シェーダー合格 |
| 戦闘モード | 自動テスト（切りかえ、ビームの命中、よろける→倒れる→起き上がる→元の場所、歩く人の再開、座る人は身をすくめるだけ、パンチ、効果の後片付け、視野角の復帰、効果音 7 種の音量） | 29 項目すべて合格 |

## 6. 動作の重さ（目安）

- シーン全体：描画する物体 約 1,500、三角形 約 290 万（草は別に GPU インスタンシング）。PC 向けの高画質を想定しています。
- 重いときの対策（Inspector）：**Lawn Grass**（立体的な草）をオフ、**Ambient People**（歩く人・座る人）をオフ、**Render Scale** を 1.0 以下、**Post Processing** をオフ。
- 実機での速度は未計測です。気になる場合は、Unity の Stats 表示（Game タブ右上）の FPS を教えてください。調整します。

## 7. 外部アセットについて

- **今回、外部アセット（アセットストアの購入品・他者の素材）は使っていません。** シェーダー・モデル・テクスチャ・効果音は、すべてこのプロジェクトのコードと Blender スクリプトで作ったものです。
- 制作に使った道具：Blender（無料、GNU GPL。Blender で作ったモデルの権利は制作者にあり、プロジェクトの配布に影響しません）、Python・NumPy・Pillow（いずれも無料のオープンソース）。これらはモデルを作り直すときだけ必要で、Unity のプロジェクトには入りません。
- 今後さらに品質を上げる選択肢（例：骨格つきの人物モデルと動き、表情のアニメーション）で外部アセットが必要になった場合は、導入前にライセンス・費用・導入方法を確認してお知らせします。

## 8. 元にもどす方法

1. **いちばん確実な方法**：10/15 版の ZIP（`FutureCity_Unity_1of2.zip`・`2of2.zip`）を保管しておき、`Assets/FutureCity` と `Assets/FutureCityPhotos` をその中身に入れかえて、Create Scene をやり直す。
2. **見た目だけもどす**：シーンの `FutureCity` オブジェクトの Inspector で **Anime Style** をオフ → Play（従来の実写風と 360°写真の背景）。
3. **戦闘モードだけ止める**：Inspector の **Combat Mode** をオフ。

## 10. 今後の改善案

- 人物を骨格（ボーン）つきのモデルにして、歩き・座り・会話のしぐさを本格的なアニメーションに（現在は関節ごとの回転）
- 顔の影を整える（アニメの顔用の影の作り方）、表情の切りかえ
- 湖畔の遊歩道・空中回廊の上など、広場の外側のエリアの作り込み
- 小物の LOD（遠くでは簡単な形に）と、同じモデルの GPU インスタンシングでさらに軽く
